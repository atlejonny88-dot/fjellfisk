## Fixes

1. Registration round: synchronous save lock, successful-save progress only,
   reviewed tanks sorted last, readers/empty tanks excluded from registration,
   save-and-next waits for the save, and failed saves retain input.
2. Daily logs: stable registration ID makes retries idempotent. Mortality reads
   the current count inside the transaction. Log, count, stock debit and stock
   history succeed or fail together. Missing/inactive/insufficient feed rejects
   the transaction. Weight-only input requires no feed selection.
3. Feed-only entries no longer copy a previous weight into a new measurement.
   Cards still find the latest positive weight among supported legacy fields.
   Historical copied values are not migrated or deleted.
4. Feed inventory: bag adjustments add/subtract kilograms from actual remaining
   stock instead of restoring already consumed feed. Adjustment retries have an
   operation ID. Metadata/history writes are batched. Default initialization is
   transactional and is not attempted by readers. Mutation callbacks are locked.
5. Weight samples: sample and ordinary weight log are one transaction with a
   stable sample ID; current tank activity is checked. Failed saves keep the
   weight list. Invalid/nonfinite weights are rejected. Saving blocks editing
   and repeated submission.
6. Fish transfer: guarded UI, one transaction, retry ID, current source and
   target counts, existence checks, matching incoming/outgoing logs. Tanks with
   the same ID in different sections are no longer incorrectly excluded.
7. Legacy data: common finite numeric conversion handles comma decimals,
   missing fields, wrong types, NaN and Infinity. Weight aliases are supported
   in charts/FCR/history/Excel. Malformed diary timestamps no longer throw.
8. Reports: inactive tanks no longer contribute feed/mortality/temperature or
   registrations. Average weight excludes fish with no known weight. FCR uses
   the shared safe weight window and refuses transfers/invalid gain. Incomplete
   fed-tank data prevents a misleading aggregate FCR. Period boundaries use
   local calendar dates. Cached report futures prevent stale-filter exports.
9. Excel: screen and workbook use the same report. Three-sheet encode/decode
   regression tested; negative weight changes and weight aliases preserved.
10. Login preserves intentional password whitespace, disposes controllers and
    scrolls on narrow/keyboard-height layouts. Loading errors in history,
    inventory and sections are readable; technical details stay in logs.
    Kar info no longer stays on 'Beregner...' after a failed request.
11. Tank note creation has a synchronous duplicate-save lock and stable document
    reference. Existing permission-denied fallback in the overview is retained.

## Firestore rules: local changes only

An emulator regression test first reproduced denial of a legacy profile without
`disabled`. `activeUser()` now uses a false default for that missing field,
matching the existing Flutter behavior. Missing roles default to reader.
Invitation email comparisons are case-insensitive, matching the client.

Tests confirm anonymous/unknown/disabled users cannot access production; readers
cannot mutate production, stock, notes, samples or roles; employees cannot change
roles or structure; invitations cannot elevate the granted role; diary author
and archive permissions are enforced. Denial logs in these tests are expected.

`firestore.rules` has NOT been deployed. Hosting-only deployment does not deploy
these changes. Review the rule diff and agree its rollout before declaring the
legacy-profile/invitation bugs fixed in production. No rules were loosened for
anonymous production access and no emulator test contacted a production database.

## Web update mechanism

- `tool/prepare_web_release.cjs` hashes the delivered files and assets into a
  deterministic SHA-256 build ID, stamps `index.html` and writes `release.json`.
  It is also a Hosting predeploy hook; it does not compile or deploy anything.
- `web/app-update.js` checks after 15 seconds, then every five minutes while
  visible, plus throttled focus/online checks. Same/malformed/offline responses
  do not prompt. 'Senere' dismisses that build until a later session.
- 'Oppdater na' asks about unsaved edits, blocks during guarded writes, and
  replaces the current URL with a build query parameter while retaining the
  existing query and hash. It does not clear authentication or other storage.
- Bootstrap does not install a new Flutter offline service worker. Cleanup is
  restricted to the legacy Flutter worker and named Flutter caches, not unrelated
  origin storage or service workers.
- Hosting revalidation headers cover the root, bootstrap, scripts, version files
  and rewritten routes. The catch-all uses a regex because the installed Windows
  emulator converts glob slashes to backslashes. Both the mismatch and its fix
  were reproduced locally. Current caching is deliberately conservative.
- Already-open old releases without this checker cannot gain it remotely. They
  need one normal reload/reopen; subsequent releases can show the update banner.

## Release gate and reproducible commands

Both `develop` and `main` still require one approval, enforce protection for
administrators, and prohibit force push/deletion. Feature PR must be approved
and merged to develop, followed by a reviewed develop-to-main PR. A PR author
cannot approve their own PR; an eligible separate reviewer is required.

Do not deploy from this feature branch. After reviews and acceptance, use clean
main, rerun all checks/builds, stamp the fresh web build, confirm the Firebase
project `trolltungaarctictrout`, and deploy Hosting only. Rules require the separate
review/rollout decision above. Never upload the verification APK/AAB.

Local rules tests (with Java 21 on PATH):

```powershell
npm ci --ignore-scripts --prefix tool/rules
firebase emulators:exec --config firebase.qa.json --project demo-fjellfisk-qa --only firestore "node --test tool/rules/rules.test.cjs"
```

Local web checks after a fresh release build:

```powershell
node tool/prepare_web_release.cjs
node --test tool/web_update.test.cjs
firebase emulators:exec --project demo-fjellfisk-qa --only hosting "node tool/hosting_headers.cjs"
node tool/web_smoke.cjs
```

`web_smoke.cjs` requires Playwright in the local tooling environment (or NODE_PATH)
and Chrome. Its HTTP server binds only to localhost and closes after the test.
No test script deploys or supplies production write credentials.
